# 知识库存储与索引优化方案

> 状态：优化点 1、2、3 均已落地（三分支增量、标点切块、混合检索 + Rerank 最终 Top-2）。  
> 范围：增量决策、切块、混合召回与精排；Ask 编排结构不变，最终 Top-2 会直接影响送给 LLM 的材料。

本文约定已认同的优化点，每个点只写清：**现状是什么 → 打算怎么优化**。

---

## 优化点 1：重嵌规则与元数据更新

索引时要回答：**这篇文档这次要不要动、动到什么程度？**

### 现状

```text
同路径 + 正文 content_hash 相同 + 已 indexed → 整篇跳过
否则 → 删旧向量 → 重新切块 Embedding → 写入（全量重嵌）
```

| 实际变化 | 现在会怎样 | 问题 |
|----------|------------|------|
| 正文变了 | 全量重嵌 | 正确 |
| 只改标题或更新时间 | **整篇跳过** | SQL / Chroma 的 title、updated_at 仍是旧值，按标题/时间过滤不准 |
| 换了 Embedding 模型 | **整篇跳过** | 新旧向量混库，相似度不可比 |

只认「正文有没有变」，不认元数据与模型变化。

### 打算怎么优化

拆成三种动作：

| 动作 | 什么时候 | 做什么 |
|------|----------|--------|
| **完全跳过** | 正文、标题、更新时间、模型都没变 | 不动 |
| **只更新元数据** | 正文和模型没变，标题或更新时间变了 | 更新 SQL 与 Chroma 的 title / updated_at；**不重算向量** |
| **全量重嵌** | 新文件 / 正文变了 / 换了模型 / 强制重建 | 删旧 → 切块 → Embedding → 写入 |

一句话：向量过期 → 重嵌；只有过滤字段过期 → 刷元数据；都没过期 → 跳过。

## 优化点 2：长文本切块按标点，不按字数硬切

### 现状

先按空行分段，短段合并；**超过 `chunk_size` 的长段再按固定字符窗口硬切**（带 overlap）。  
长句、长段容易从句子中间断开，单块语义不完整，向量检索更难对准「一整句/一层意思」。

### 打算怎么优化

超长段优先在 **句号、问号、叹号等标点**（如 `。！？；` 及对应英文标点）附近切开，尽量保持句子完整。  
仍可保留长度上限：找不到合适标点时，再退回字数切分作为兜底。

目标：块边界对齐自然语言，而不是对齐字符计数。

## 优化点 3：混合检索 + Rerank 精排，最终 Top-2 送给 LLM

### 现状

检索只有 **Chroma 向量一路**：按相似度取 Top-K 后直接使用（Ask 时整份 hits 交给 LLM）。  
问题：

- 专名、人名等 **字面词** 容易漏（向量不稳）  
- 同义改写靠向量可以，但排序不一定准  
- Top-K 里可能夹杂弱相关片段，干扰回答  

（原先「相关度阈值 0.5」可作为粗过滤手段，本点改为更完整的召回 + 精排方案后不再作为本点主方案。）

### 打算怎么优化

改成三层漏斗，**最终只保留 2 条** 最高质量材料给 LLM：

```text
用户问题
  ├─ 向量检索（Chroma）        → fetch_k 条
  └─ 关键字检索（FTS5 + BM25） → fetch_k 条
           ↓
      RRF 融合 → candidate_k 条（混合粗排结果）
           ↓
      Reranker 精排（如 bge-reranker）
           ↓
      取最终 Top-2 → 送给 LLM 生成回答
```

| 阶段 | 做什么 | 目的 |
|------|--------|------|
| **混合召回** | 向量路 + 关键字路各取 `fetch_k`，RRF 合并为 `candidate_k` | 语义命中与字面命中互补，提高召回 |
| **Rerank 精排** | 对 `(问题, chunk 正文)` 用 cross-encoder 重打分并重排 | 提高排序精度 |
| **截断 Top-2** | 只把精排后的前 2 条交给 Ask / LLM | 少而准，降低干扰与幻觉 |

约定：

- `fetch_k ≥ candidate_k ≥ 2`：本方案取 **fetch_k=5，candidate_k=5，最终 top_k=2**  
- 关键字路：chunk 入库时同步维护 `chunk_fts`（jieba 分词写入）；查询时 `MATCH` + 内置 `bm25()` 排序再 `LIMIT fetch_k`  
- Reranker：本地模型优先 `BAAI/bge-reranker-v2-m3`（与现有 BGE 系一致）  
- Ask 编排（rewrite → retrieve → answer）结构可不变，只升级 `search_knowledge_base`（或等价检索入口）的内部实现；**Ask 默认最终命中数为 2**

一句话：先混合找全，再精排找准，最后只扔 **2 条** 给 LLM。

## 不在本次范围

邻块合并、Ask 改写策略、上传后自动索引、换 Embedding 模型选型、相关度阈值调参细节等，另议。
